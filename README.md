# BIREQDAR&CO. concept preview

A responsive Version One storefront and owner studio for BIREQDAR&CO. It supports product browsing, reservations, a persistent jewellery/bullion bag, checkout orders, inventory, collections, order management and customer enquiries. It uses Node.js built-ins only and keeps orders and products in `data/store.json`, a small local JSON database file rather than a separate database server. Back up this file and the `uploads/` folder together. All seeded products/prices are clearly marked sample listings. Public pages remain `noindex,nofollow` while the business details are being verified.

## Run Version One locally

Use Node.js 20 or newer. From this folder, run:

```sh
npm start
```

Optional: copy `.env.example` to `.env` to set local options. Open `http://localhost:3000`. On first start, the server prints a one-time owner setup key. Open `/admin.html`, use that key to create the owner username and password, then manage the catalogue from Owner Studio. Do not start the old static Python server; the storefront uses the API in `server.js`.

## Deployment

This V1 needs a Node.js host with a persistent writable disk. The product store and uploaded photographs live in `data/` and `uploads/`; serverless hosting with temporary storage will lose them. Configure a verified domain and the private environment variables shown in `.env.example`. Set `HOST=0.0.0.0` on a host such as Render (the local default binds only to your own computer). For real payments, configure Stripe and a webhook at `https://YOUR_DOMAIN/api/stripe-webhook` for `checkout.session.completed`. Keep `noindex,nofollow` until the owner approves launch.

Before opening the store, replace all preview listings, confirm product and delivery details, configure taxes, privacy/returns information, and connect Stripe. Production URL, canonical metadata, social image, sitemap and `robots.txt` also need the final domain.

## Publish with GitHub and Render

This app needs a Node.js web service plus persistent storage; GitHub Pages alone cannot run its server or save orders. The included `render.yaml` configures a Render web service with a persistent disk for the JSON store and uploaded product images. Render documents that persistent disks require a paid web-service plan and preserve only data written under the disk mount path. Review the plan and disk charges in your Render account before creating the service.

1. Create a **private** GitHub repository and push this project’s `main` branch.
2. In Render, choose **New → Blueprint**, connect the private repository, and approve the `render.yaml` service and persistent disk.
3. Once it deploys, use the service URL to open `/admin.html`. The setup key is generated by Render; read it in the service logs, then immediately create the owner login.
4. Add the final custom domain and set `APP_URL` to its HTTPS URL in Render before configuring Stripe. Render’s generated HTTPS URL is detected automatically for secure cookies and preview checkout redirects.
5. Configure Stripe keys as Render environment variables only. Never add production secrets to GitHub.

The JSON database and product images are stored on the persistent disk, not in Git. Keep a separate backup of the Render disk data before launch and on a regular schedule. A disk-backed single Node service is suitable for this small V1; it is not designed to run multiple app instances.

## Owner Studio

- Products: add/edit/remove items, upload a photo, set price, stock, type, collection, specifications, draft/published status, enquiry-only status and sample/live status.
- Jewellery styles: assign necklaces, pendants, earrings, bracelets or rings to products; customers can filter by style in Shop.
- Collections: add, hide/show and remove collections. A collection must be empty before removal.
- Orders: view customer/order details and update processing/fulfilled/cancelled status. Paid status is set by the Stripe webhook.
- Enquiries: watch reservations and product questions are saved for follow-up and can be marked new/contacted/closed.
- Settings: select GBP/EUR/USD (all listings update together); set delivery fee (blank means undecided); enable automatic tax only after it is configured in Stripe.
- Store bag is kept in the visitor’s browser. The server validates products, prices, quantities and stock during checkout.

## Checkout and launch limits

- Without Stripe credentials, checkout records a clearly labeled preview order and takes no payment.
- Sample products cannot be charged in Stripe live mode. Replace them with verified listings and uncheck “Sample preview listing” before live payment.
- Live checkout is blocked until a delivery fee (including 0 for complimentary delivery) and Stripe automatic tax are configured. Stripe test mode can be used for integration testing.
- Delivery labels/fulfilment, taxes, returns, email receipts, customer support contacts and legal/privacy text still need the owner’s verified setup. Stripe payment keys and webhook must be configured before real card payments.
- The JSON store is suitable for a small V1 deployment on one persistent Node server. For multiple server instances or higher order volume, move the data to a managed database before scaling.

## Pre-launch checklist

- Replace every preview/sample listing with actual products, verified prices, stock, grading and approved product photographs.
- Add payment provider credentials, delivery rules, tax settings, privacy details and public contact information.
- Verify every specification, price, availability statement, origin and brand-history claim.
- Configure an enquiry email provider if you want email notifications; currently enquiries are stored in Owner Studio for manual follow-up.
- Review the privacy notice with your business details and actual data practices.
- Review the finished desktop and mobile site, choose the final domain, then add canonical metadata, a social-sharing image and sitemap.
- Remove `noindex,nofollow` only after you approve public launch.


### Tax/VAT preview

Product listings default to the 20% standard VAT rate. VAT calculations are disabled until the owner marks the business as UK VAT-registered in Owner Studio. Once enabled, checkout extracts estimated VAT from VAT-inclusive prices for UK delivery addresses, without adding it on top of the displayed price. The product editor allows 0% for products that have been verified as exempt or zero-rated. For live card payments, Stripe Tax must be configured and the owner must confirm the correct tax treatment and Stripe tax code for each product. In particular, do not classify bullion as exempt unless it qualifies as investment gold under HMRC rules. This preview is an estimate, not tax advice.

Customer account navigation currently opens a client account information page; customer authentication is not enabled in this version.
